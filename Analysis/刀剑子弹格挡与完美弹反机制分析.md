# 刀剑子弹格挡、完美弹反与近战防守反击机制分析（留档）

## 结论摘要

- **普通格挡挡子弹**：需要满足可挡子弹前置（刀剑、远程来袭、技能达标、朝向达标）并处于格挡/偏斜状态。
- **普通反弹（Deflect）**：在格挡状态下，若解锁对应技能并且耐力超过阈值，可触发 `WasBulletDeflected`。
- **完美弹反（Parry）**：在“短时间 Deflect 窗口”内命中子弹时触发 `WasBulletParried`，属于“击中瞬间格挡”机制。
- **反弹落点可控到准星附近**：仅 `IsBlocking` 触发 `WasBulletDeflected` 时，也会沿准星方向反弹；在子弹时间激活或 `WasBulletParried` 时，会进一步做“准星附近敌人组件/胸口位”的目标吸附，命中更稳定。
- **近战防守反击（玩家侧）**：不是“按住格挡后自动反击”，而是 **`MeleeDeflect`（按下格挡的短窗口）→ 命中判定 `WasDeflected` → `successfulDeflect` → `MeleeDeflectAttack`（防守反击攻击态）**。
- **`MeleeBlockAttack` 不是防守反击**：那是按住格挡时再按攻击键的主动格挡攻击（guard bash），与防反状态机无关。
- **自动完美弹反/防反方案**：
  - **思路一**：命中前 Observe 威胁 → 模拟进入 `MeleeDeflect` 窗口 → 交给原版链条（见 §9）。
  - **思路二**：直接改判定与 PSM，强制只走完美分支并驱动 `MeleeDeflectAttack`（见 §10）。仅改 `IsDeflecting` **不够**（实测与脚本均证实）。

## 1) 子弹可被刀剑防御的前置条件

位置：`damageManager.swift` 的 `CanBlockBullet(hitEvent)`

核心判定：

1. 防御武器存在。
2. 防御武器是刀剑（`IsBlade()`）。
3. 来袭攻击必须是远程（`AttackData.IsRangedOnly(...)`）。
4. 玩家已解锁里程碑技能并达到阈值（`Reflexes_Right_Milestone_2 >= 2`）。
5. 朝向与视角判定通过（不是全方向）。

这一步只决定“**能不能进入刀挡子弹体系**”。

## 2) 命中瞬间如何分流：Block / Deflect / Parry

位置：`damageManager.swift` 的 `ProcessDefensiveState(hitEvent)`

调用链（同步）：

`DamageSystem.PreProcess` → `DamageSystem.ModifyHitData` → `DamageManager.ModifyHitData` → `DamageManager.ProcessDefensiveState`

### 2.1 近战分支（先于子弹分支）

条件：`AttackData.IsMelee` 且朝向合法（`IsValidDirectionToDefendMeleeAttack`；默认 `meleeMaxDefendAngle = 45°`）。

分流：

| 条件 | 命中标记 | 后续 |
|---|---|---|
| `IsDeflecting == 1` 且攻击不是 `QuickMelee` | `WasDeflected`（reason: `Parry`） | 对攻击者推 `myAttackParried` / `MyAttackParried`；若目标是玩家，再 `SendNameEventToPSM("successfulDeflect")` |
| `IsBlocking == 1` 且攻击 record 未 `CanSkipBlock()`，或 `IsDeflecting` 且来袭为 `QuickMelee` | `WasBlocked` | 耐力消耗 `DealStaminaDamage`；对攻击者推 Block 信号 |
| 否则 | 无防御标记 | `HitSignal` / `MyAttackHit` |

注意：`QuickMelee` 在 `IsDeflecting` 下不会进 Parry，只会落到 Block 分支。

### 2.2 子弹分支

在子弹分支里（`currentStamina > 0 && CanBlockBullet`）还会检查：

- `IsBlocking == 1` 或 `IsDeflecting == 1`。

之后分流：

- 若已购入 `Reflexes_Right_Perk_2_1` 且耐力充足：
  - `IsBlocking == 1` → 标记 `WasBulletDeflected`
  - `IsDeflecting == 1` → 标记 `WasBulletParried`
- 否则仅 `WasBulletBlocked`（普通挡住，不进入弹反）

**Blocking 优先于 Deflecting**：同帧若 `IsBlocking == 1`，子弹侧永远先走 `WasBulletDeflected`，进不了 `WasBulletParried`。

耐力阈值公式：

`currentStamina > totalStamina * Reflexes_Right_Milestone_2_StaminaDeflectPerc`

注意是**严格大于**，不是大于等于。

## 3) “完美弹反窗口”来自哪里

位置：`meleeTransitions.swift`

关键状态：`MeleeDeflect`

- 进入条件：按下格挡、武器可弹反、未禁用、无冷却等。
- 该状态有短持续时间（默认参数 `duration = 0.40`，具体可被配置覆盖）。
- 进入状态时给玩家加上 `IsDeflecting = 1`。
- 退出状态时移除 `IsDeflecting`，并启动 `Deflect` 冷却。

因此，“**子弹/近战命中瞬间按格挡触发完美防御**”本质就是：

- 命中时刻玩家是否处于 `IsDeflecting` 的短窗口内。

## 4) 反弹弹道为何能靠近准星

位置：`damageSystem.swift` 的 `ProcessBulletDeflect(...)`

核心流程：

1. 先读取当前准星数据（`GetDefaultCrosshairData`）。
2. 若满足：
   - 子弹时间激活（`Reflexes_Right_Perk_2_3` + Time Dilation Active），**或**
   - 本次命中是 `WasBulletParried`（完美弹反）
3. 则寻找准星最近敌人，并将目标点尽量修正到：
   - 目标组件位置（角度足够小时），
   - 或胸口槽位，
   - 或目标世界坐标。
4. 再基于该点生成反弹攻击（`..._Deflect` / `..._ParryDeflect`）。

所以体感上会出现两层效果：

- 仅 `IsBlocking`：反弹已会“沿准星方向”走。
- `WasBulletParried` 或子弹时间：在“沿准星方向”基础上，再叠加目标吸附，表现为更像自动贴准星目标。

### 4.1 实测修正说明（与你当前 Ninja 配置一致）

你当前脚本常驻 `IsBlocking` 后，确实可在不进入 `IsDeflecting` 的前提下实现“反弹到准星方向”的体感。这与早期文字表述的差异点在于：

- 早期描述强调的是“目标吸附到敌人组件/胸口”这一层（需要 `WasBulletParried` 或子弹时间）。
- 但“沿准星方向反弹”本身并不要求 `IsDeflecting`，`WasBulletDeflected` 路径也能做到。

已按此结论修正文档。

## 5) 脚本层：`IsBlocking` 与 `IsDeflecting` 的施加条件

下面只讨论**脚本层可见**逻辑（PSM 决策/事件），不含 native 层内部调度细节。

### 5.1 `IsBlocking`（原版脚本）

`IsBlocking` 由 `MeleeBlockEvents.OnEnter()` 施加，`OnExit()` 移除。

其进入前置由 `MeleeBlockDecisions.EnterCondition()` 决定，主要条件：

1. 玩家处于“按住格挡”状态（`IsBlockHeld`：UpperBody 黑板 == 6）。
2. 当前不是被招架状态（`!IsAttackParried`）。
3. 武器具备格挡能力（`CanWeaponBlock`）。
4. 非“近战瞄准+可投掷”冲突分支（`HasMeleeTargeting && CanThrowWeapon` 时拒绝）。
5. `Block` 与 `Deflect` 冷却均未激活。

满足后进入 `MeleeBlockEvents.OnEnter()`：

- 设置状态位并播放 `Block` 动画。
- 施加 `gamedataStatType.IsBlocking +1`。

退出时在 `OnExitCommon()` 中移除该 modifier。

### 5.2 `IsDeflecting`（原版脚本）

`IsDeflecting` 由 `MeleeDeflectEvents.OnEnter()` 施加，`OnExit()` 移除。

其进入前置由 `MeleeDeflectDecisions.EnterCondition()` 决定，主要条件：

1. 玩家触发“格挡按下”（`IsBlockPressed` = `IsActionJustPressed("MeleeBlock")`，强调按下边沿而非一直按住）。
2. 武器具备弹反能力（`CanWeaponDeflect`）。
3. 不能处于近战瞄准状态（`!HasMeleeTargeting`）。
4. 配置未禁用（`disabled` 参数为 false）。
5. `Deflect` 冷却未激活。

满足后进入 `MeleeDeflectEvents.OnEnter()`：

- 播放 `Deflect` 动画（`PushAnimationEvent("Deflect")`）。
- AimSnap。
- 施加 `gamedataStatType.IsDeflecting +1`。
- MeleeWeapon 黑板设为 `10`（`gamePSMMeleeWeapon.Deflect`）。

退出时移除 modifier，并启动 `Deflect` 冷却。

### 5.3 两者关系（脚本层结论）

- `IsBlocking` 更偏“持续防御态”（按住维持）。
- `IsDeflecting` 更偏“瞬时窗口态”（按下触发 + 持续时间/冷却控制）。
- 两者都可进入子弹防御分支，但命中标记不同：
   - `IsBlocking` 倾向 `WasBulletDeflected`
   - `IsDeflecting` 倾向 `WasBulletParried`
- 近战侧：只有 `IsDeflecting` 才能打出 `WasDeflected`（完美招架）；`IsBlocking` 只能 `WasBlocked`。

## 6) 近战防守反击（Melee Deflect → DeflectAttack）

本节对应游戏内“格挡瞬间招架并反击”的玩家侧机制。

### 6.1 完整状态链

```
按下 MeleeBlock (JustPressed)
        │
        ▼
 MeleeDeflect  (duration≈0.40s, IsDeflecting=1, 播 Deflect 动画)
        │
        │  敌方近战命中落在窗口内
        ▼
 ProcessDefensiveState
   → WasDeflected + DontShowDamageFloater
   → PushEvent(instigator, myAttackParried)
   → SendNameEventToPSM("successfulDeflect")   // 仅目标为玩家
        │
        ▼
 MeleeDeflect.ToMeleeDeflectAttack
   ← stateContext 临时参数 successfulDeflect.valid
        │
        ▼
 MeleeDeflectAttack  (MeleeWeapon 黑板=20)
   → 读取武器攻击 record：状态名 "MeleeDeflectAttack" + attackNumber
   → 播放反击攻击动画 / 生成攻击 effect
   → 短时 time dilation（name="deflect"）
```

### 6.2 伤害侧：招架成立条件（玩家被近战打中）

位置：`DamageManager.ProcessDefensiveState` 近战分支。

同时满足：

1. `AttackData.IsMelee(...)`
2. 朝向合法：`IsValidDirectionToDefendMeleeAttack(instigator.forward, target.forward)`（默认 45° 扇区）
3. `GetStatValue(IsDeflecting) == 1`
4. 攻击类型 **不是** `QuickMelee`
5. 目标是玩家（或 NPC 黑板 `attackParried == true`；NPC 侧另见 `MeleeHitAnimEventExecutor`）

成立后：

- `hitFlag.WasDeflected`
- 玩家侧 `QueueEvent(PSMPostponedParameterBool{ id=successfulDeflect, value=true })`（玩家与武器实体各一份）

后续在 `DamageSystem.ProcessBlockAndDeflect`：

- `WasDeflected` / `WasBlocked` 时近战伤害系数通常置 0（拳击对非拳等特例除外）
- `WasDeflected` 时调用 `RPGManager.AwardExperienceFromDeflect`

### 6.3 状态机侧：为何必须已在 `MeleeDeflect`

`MeleeDeflectDecisions.ToMeleeDeflectAttack`：

```text
return stateContext.GetTemporaryBoolParameter("successfulDeflect").valid
```

该转移定义在 **`MeleeDeflect` → `MeleeDeflectAttack`**。  
若命中时玩家不在 `MeleeDeflect`：

- 仅注入 `IsDeflecting` 仍可使 **伤害侧** 打上 `WasDeflected`（免伤/经验）
- `successfulDeflect` 仍会被 Queue
- 但 **没有** 从其他近战态监听该参数并转入 `MeleeDeflectAttack` 的脚本路径
- 结果：**无防守反击动画、无 DeflectAttack 攻击 record、无防反慢动作**

因此：完整防反 = **窗口态（MeleeDeflect）先成立**，再叠命中判定；不是命中后再补按键。

### 6.4 `MeleeDeflectAttack` 进入与表现

- `MeleeDeflectAttackDecisions.EnterCondition`：武器必须存在对应攻击 record（`HasAttackRecord` → `GetAttack("MeleeDeflectAttack" + N)`）。无 record 的武器进不了反击态。
- `OnEnter`：MeleeWeapon 黑板 `20`（`DeflectAttack`），教程 fact `melee_deflect_tutorial`，rumble，可选慢动作起始音效。
- `OnUpdate`：入态约 `slowMoStart`（默认 0.10s）后施加 `TimeSystem.SetTimeDilation("deflect", ...)`。
- 反击命中敌人时，攻击 subtype 可为 `gamedataAttackSubtype.DeflectAttack`；若玩家点了 `Reflexes_Right_Perk_2_2`，暴击与受击反应等级会额外加强（见 `damageSystem` / `hitReactionComponent`）。

### 6.5 与 `MeleeBlock` / `MeleeBlockAttack` 的区别

| 机制 | 输入 | 命中标记 | 是否自动反击 |
|---|---|---|---|
| `MeleeDeflect` → `MeleeDeflectAttack` | 格挡 **按下边沿**，命中落在短窗口 | `WasDeflected` | **是**（自动进 DeflectAttack） |
| `MeleeBlock` | 格挡 **按住** | `WasBlocked` | **否**（只挡，耗耐力） |
| `MeleeBlockAttack` | 按住格挡时再 **按攻击键** | 主动攻击，非防御命中分流 | 否（玩家主动出招） |

按住格挡挡住近战 ≠ 防守反击。防反依赖 Deflect 窗口，不是 Block 持续态。

### 6.6 窗口退出与冷却

`MeleeDeflect` 退出条件（节选）：

- `successfulDeflect` 有效 → 转 DeflectAttack
- 或 `GetInStateTime() >= duration`（默认 0.40）
- 或打断 / 按住格挡时又按下近战攻击等

退出 `MeleeDeflect`（未转走前的 OnExit）会：

- 移除 `IsDeflecting`
- `StartCooldown(owner, "Deflect", cooldown)`

冷却未结束时无法再次进入 Deflect 窗口。

`MeleeDeflect` 在按住格挡结束窗口后可转到 `MeleeBlock`（`ToMeleeBlock` 恒 true），即：点按窗口结束 → 若仍按住则进入普通格挡。

### 6.7 NPC 被玩家招架时的对称逻辑（补充）

位置：`executorMeleeHit.swift` 的 `MeleeHitAnimEventExecutor`

当目标 NPC `IsDeflecting == 1` 且 `MeleeParryCondition` 通过时，写黑板 `attackParried = true`。  
这与玩家侧 `ProcessDefensiveState` 中对非玩家目标要求 `attackParried` 黑板为 true 的分支对应，属于 NPC 招架管线，不是玩家防反主路径。

## 7) Mod 思路评估：ObserveBefore 改 stat vs 模拟按格挡键

### 7.1 仅 `ObserveBefore(ModifyHitData)` + 注入 `IsDeflecting`

| 目标 | 是否生效 |
|---|---|
| 近战免伤 / `WasDeflected` | 可以（同帧 `GetStatValue` 能读到） |
| 子弹 `WasBulletParried` | 可以（仍需 `CanBlockBullet`、技能、耐力；且需压掉 `IsBlocking`） |
| 完整 Deflect 动画 | **否**（未进 `MeleeDeflect`） |
| 近战防守反击 `MeleeDeflectAttack` | **否**（转移只挂在 `MeleeDeflect` 上） |

适用：只要判定结果、不要完整 PSM/动画。仓库 `Knife`/`Ninja` 的 DeflectMod（`IsDeflecting+1` + `IsBlocking-2`）属于这一类。

### 7.2 在 `ObserveBefore(ModifyHitData)` 里“替玩家按一下格挡”

**对当前这一击：不可行（过晚）。**

原因：

1. `IsBlockPressed` → 进入 `MeleeDeflect` → `OnEnter` 施加 `IsDeflecting`，发生在 **PSM 更新/转移**，不是伤害管线内部同步步骤。
2. `ProcessDefensiveState` 与 `ObserveBefore(ModifyHitData)` 处于**同一次** `PreProcess` 调用栈；此时模拟输入无法让 `MeleeDeflect.OnEnter` 在本帧判定前执行完。
3. 因此当前命中仍读不到由状态机施加的 `IsDeflecting`；最多影响**后续**若干帧的窗口。

结论：要完整动画 + 防反，必须在 **命中发生之前** 就让玩家进入 `MeleeDeflect`（提前模拟 `MeleeBlock` 按下，或等价地强制进入该 PSM 态）。

### 7.3 推荐架构（子弹完美弹反 + 近战自动防反）

**共同前提**：武器 `CanWeaponDeflect`；近战还需朝向扇区；子弹还需刀剑与技能链。

**近战自动防反（要动画）**：

1. 在命中前感知威胁（NPC 近战出手/特效阶段、攻击预警、距离+动作时间估 ETA 等——**早于** `ModifyHitData`）。
2. 提前注入 `MeleeBlock` 按下边沿（或直接请求进入 `MeleeDeflect`），保证命中帧已在 Deflect 窗口内。
3. 命中后交给原版：`WasDeflected` → `successfulDeflect` → `MeleeDeflectAttack`。
4. 注意 `Deflect` 冷却，避免连打窗口失败。

**子弹自动完美弹反**：

- 要完整 Deflect 动画：同样需要提前进入 `MeleeDeflect`（hitscan 无飞行时间，只能开火预判或极短常驻窗口）。
- 只要弹反标记、可接受无 Deflect 动画：`ObserveBefore(ModifyHitData)` 注入 stat 即可；不产生 `MeleeDeflectAttack`（子弹路径也不依赖它）。

**不推荐**：在命中回调里只按键、期望本击既免伤又出防反——时序上不成立。

### 7.4 与常驻 `IsBlocking`（如 Ninja）的冲突

常驻 `IsBlocking+1` 时：

- 子弹侧会优先 `WasBulletDeflected`，吃不到 `WasBulletParried`。
- 近战侧只会 `WasBlocked`，吃不到 `WasDeflected` / 防反。

若要完美/防反，窗口期内需压低 Blocking 读数（例如临时 `IsBlocking -2`），或确保此时不在 `MeleeBlock` 且无常驻 Blocking modifier。

## 8) 与当前 Ninja / Knife 脚本的关系

### Ninja

`Ninja` 常驻 `IsBlocking +1`：

- 提高进入“子弹防御分支”的稳定性（常态视为在挡）
- **不等于**自动 `IsDeflecting` 窗口
- 常驻 Blocking 会阻碍 `WasBulletParried` / 近战 `WasDeflected`

### Knife

`DeflectMod = IsDeflecting+1 + IsBlocking-2`，在 MeleeWeapon 状态为 Deflect(10) 时施加：

- 与原版 `MeleeDeflect` 窗口对齐时的 stat 语义一致
- 可强制 Parry 分支，但若未真正处于可转到 `MeleeDeflectAttack` 的 PSM 路径，仍可能缺反击动画

## 9) 思路一：命中前开窗（Observe 威胁 → 模拟 `MeleeDeflect`）

> 归档名：**自动完美弹反/防反 · 思路一**  
> 核心：不改原版分流逻辑，只在命中前让玩家合法进入 `MeleeDeflect`，由原版完成 `WasDeflected` / `WasBulletParried` 与 `MeleeDeflectAttack`。

目标仅限 **时间窗口内操作才能触发的特殊效果**：

- 近战：`MeleeDeflect` → `WasDeflected` → `MeleeDeflectAttack`（防守反击）
- 子弹：`MeleeDeflect`（`IsDeflecting`）→ `WasBulletParried`（完美弹反 + `ParryDeflect` 吸附等）

不讨论普通 `IsBlocking` / `WasBlocked` / `WasBulletDeflected`。

硬约束：必须在 **命中帧之前** 完成 `MeleeDeflect.OnEnter`（或等价地已持有窗口）。`ModifyHitData` 同帧再按键无效。`MeleeDeflect` 默认约 **0.40s**，提前量应落在该窗口内，并避开 `Deflect` 冷却。

### 9.1 时序总览

```
近战:
  AIAttackAttempt(isWindUp=true)     ← 最早（招式风up，UI 危险指示同源）
           │
           ▼
  AttackWithWeapon / StartAttack     ← 挥砍 effect 开始
           │
           ▼
  MeleePreAttackExecutor             ← 目标进入攻击体积时发 MeleeDodgeOpportunity
           │
           ▼
  伤害管线 ModifyHitData / ProcessDefensiveState   ← 已晚，不能再开窗口

远程 hitscan:
  ShootWithWeapon.Activate / OnStartShooting / QueueNextShot  ← 开火前（有 aimingDelay 时更早）
           │
           ▼
  AIWeapon.Fire → AI_Shoot*          ← 可能与命中同栈；按键开窗口不可靠
           │
           ▼
  AIAttackAttempt（Fire 末尾 Queue） ← 对 hitscan 往往已晚
           │
           ▼
  ModifyHitData                      ← 仅适合补 stat，不适合开 MeleeDeflect

远程实体弹:
  BaseProjectile/BaseBullet.OnShoot  ← 有飞行时间，适合开窗口
           │
           ▼
  碰撞 / 命中
```

### 9.2 近战完美防反：推荐 Observe

| 优先级 | 钩点 | 时机 | 过滤 | 评价 |
|---|---|---|---|---|
| **P0** | `AISubActionMeleeAttackAttemptEvent_Record_Implementation.Update`，或玩家侧收到 `AIAttackAttemptEvent` 且 `isWindUp == true` | 挥砍前的 windup | `evt.target` 为本地玩家；`instigator` 敌对 | **首选**。与伤害指示器 windup 同源，提前量通常足够进入 `MeleeDeflect` |
| **P1** | `ObserveBefore("MeleePreAttackExecutor", "Process", ...)` | 攻击 effect 扫到目标时 | `EffectExecutionScriptContext.GetTarget` 为玩家 | 原版用于 `MeleeDodgeOpportunity`（闪避机会）。比 windup 更贴命中，窗口更紧，但仍在命中判定前 |
| P2 | `AISubActionAttackWithWeapon_Record_Implementation.AttackWithWeapon`（`StartAttack` 前） | effect 刚启动 | owner 近战且目标指向玩家 | 覆盖面依赖 AI package；需自行判断目标 |
| 禁用 | `DamageManager.ModifyHitData` / `ProcessDefensiveState` | 命中瞬间 | — | 只能补 `IsDeflecting` 标志；**接不上** `MeleeDeflectAttack` 动画链 |

**近战动作建议**：在 P0/P1 触发时模拟 `MeleeBlock` JustPressed（或强制进 `MeleeDeflect`），然后完全交给原版 `WasDeflected` → `successfulDeflect` → `MeleeDeflectAttack`。

**注意**：

- `MeleePreAttackExecutor` 与命中 executor 同属攻击 effect，提前量可能只有 effect 扫掠的前后差；若实测过紧，以 P0 windup 为主、P1 为补。
- `QuickMelee` 即使在 `IsDeflecting` 下也不会 `WasDeflected`（走 Block 分支），自动防反应排除或单独处理。
- 朝向扇区（默认 45°）仍由 `ProcessDefensiveState` 检查；窗口开了但背对仍失败。

### 9.3 子弹完美弹反：推荐 Observe

| 优先级 | 钩点 | 适用 | 评价 |
|---|---|---|---|
| **P0（实体弹）** | `ObserveAfter("BaseProjectile", "OnShoot", ...)` / `BaseBullet.OnShoot`；或 `onUpdate` 扫 `GetProjectileSystem():GetRegisteredComponents()` | 智能弹、爆炸弹等有实体弹道 | 有飞行时间，最适合“飞近再进 Deflect 窗口” |
| **P0（hitscan 开火前）** | `AIWeapon.OnStartShooting` / `AIWeapon.QueueNextShot`；或 `AISubActionShootWithWeapon_Record_Implementation` 的 Activate/Update 中 **调用 `AIWeapon.Fire` 之前** | NPC/炮台常规射击 | 唯一有机会在 hitscan 命中前完成 `MeleeDeflect.OnEnter` 的脚本层点 |
| **P1（hitscan 开火）** | `ObserveBefore("AIWeapon", "Fire", ...)`，且 `target` 为玩家 | 所有走 `AIWeapon.Fire` 的射击 | **风险**：`AI_Shoot*` 可能在同一次 `Fire` 内同步出命中；此时按键开窗口仍可能赶不上本发，但可覆盖连发后续几发 |
| P2 | `Fire` 末尾的 `AIAttackAttemptEvent`（无 windup） | 同上 | 排在 `AI_Shoot*` **之后**，对 hitscan 本发基本过晚；可作辅助确认 |
| 禁用（要动画时） | 仅 `ModifyHitData` ObserveBefore | 任意远程 | 可强行 `WasBulletParried`（再压 Blocking），但无 `MeleeDeflect` 动画；与“完整反馈”目标不符 |

**子弹动作建议**：

1. 实体弹：ETA 进入 Deflect 窗口前缘时再按格挡（避免过早吃完 0.40s）。
2. hitscan：在 **Fire 之前**（OnStartShooting / QueueNextShot / Shoot subaction）开窗口；不要依赖 Fire 之后的 AttackAttempt。
3. 若实测 hitscan 仍同帧命中：需要更早威胁（瞄准玩家、激光、charging FX）或接受“首发用 stat 补救 + 按键服务后续发”的混合策略——但混合已偏离纯窗口语义，应单独标注。

### 9.4 统一过滤器（两种完美效果共用）

触发开窗前建议校验：

1. 本地玩家存活、持近战且 `CanWeaponDeflect`
2. 子弹路径另需刀剑 + `Reflexes_Right_Milestone_2` / `Perk_2_1` / 耐力阈值（否则进了窗口也只是 Block）
3. `Deflect` 冷却未激活；当前未在 `MeleeDeflect`（避免重复边沿）
4. 威胁目标是玩家；来袭非友军
5. 近战：非 `QuickMelee`（若能从 attack record 分辨）
6. 不要在开窗同时维持更高的 `IsBlocking`（否则子弹优先普通弹反、近战优先普通格挡）

### 9.5 点位选择结论（只做完美窗口）

| 需求 | 主 Observe | 备选 | 明确不要 |
|---|---|---|---|
| 近战自动防反（含反击动画） | Windup：`AIAttackAttemptEvent(isWindUp)` / MeleeAttackAttempt subaction | `MeleePreAttackExecutor.Process` | `ModifyHitData` |
| 子弹完美弹反（实体弹） | `BaseProjectile.OnShoot` + 距离/ETA | `GetRegisteredComponents` 轮询 | 命中后再按键 |
| 子弹完美弹反（hitscan） | `OnStartShooting` / `QueueNextShot` / Shoot subaction（Fire 前） | `ObserveBefore AIWeapon.Fire`（连发友好，首发存疑） | Fire 后的 AttackAttempt；仅 ModifyHitData |

思路一依赖“提前量 + 原版窗口”；hitscan 首发与过紧的 PreAttack 是主要风险点。完整链路控制见思路二（§10）。

## 10) 思路二：强制完美分支 + 打通整条防反链

> 归档名：**自动完美弹反/防反 · 思路二**  
> 核心：不依赖玩家是否已在 `MeleeDeflect` 窗口；在命中时**改写判定**只走完美分支，并**主动驱动**原版里负责反击动画与 `deflect` 慢动作的那一段（`MeleeDeflectAttack`），而不是只改一个 stat。

### 10.1 为何“只改 `IsDeflecting`”不够（与实测对齐）

近战完美招架在脚本里拆成 **至少两段、不同系统**：

```
[A 伤害/AI 段]  ProcessDefensiveState
                  IsDeflecting==1 → WasDeflected
                  → PushEvent(instigator, myAttackParried) / MyAttackParried
                  → SendNameEventToPSM("successfulDeflect")   // 仅 Queue，不保证有人消费
                  → 后续 ProcessBlockAndDeflect：免伤、AwardExperienceFromDeflect 等

[B PSM 反击段]  仅当当前态是 MeleeDeflect 时
                  ToMeleeDeflectAttack ← temporaryBool successfulDeflect.valid
                  → MeleeDeflectAttack.OnEnter / OnUpdate
                     · MeleeWeapon 黑板 = 20 (DeflectAttack)
                     · super.OnEnter → 加载武器 "MeleeDeflectAttackN" record、播攻击动画、生成攻击 effect
                     · SetTimeDilation(name="deflect", ...)
```

| 只改 `IsDeflecting` 时 | 结果 | 对应系统 |
|---|---|---|
| 挡住伤害 | 有 | A：`WasDeflected` + `ProcessBlockAndDeflect` |
| 敌人异常震慑（强于普通格挡） | 有 | A：`myAttackParried` / `MyAttackParried`（普通 Block 走的是 `myAttackBlocked`） |
| 玩家防守反击动画 | **无** | B：未进入 `MeleeDeflectAttack` |
| `deflect` 时间膨胀 | **无** | B：只在 `MeleeDeflectAttackEvents.OnUpdate` |

补充：`PlayerPuppet.OnHitBlockedOrDeflected` 在 `WasDeflectedAny` 时对**近战招架**推的是 `MeleeBlock` 动画事件，**不是** `MeleeDeflectAttack`。因此命中反馈里的“格挡感”≠ 防反连招。

结论（与实测一致）：`IsDeflecting` 只渗透了 **A 段**；动画 + 慢动作在 **B 段**。思路二必须渗透 **A+B**。

### 10.2 近战完整链条上必须打通的节点

按执行顺序：

| # | 节点 | 原版条件 | 思路二要做什么 |
|---|---|---|---|
| 1 | 进入近战防御分支 | `IsMelee` + 朝向扇区 | Override/`ObserveBefore` 放宽或恒真（可选：保留朝向则更“原版感”） |
| 2 | 完美招架而非普通格挡 | `IsDeflecting==1` 且非 `QuickMelee` | **直接走 `WasDeflected` 分支**（可不再依赖真实 `IsDeflecting`），或同帧注入再读 |
| 3 | 禁止落到 Block | 不要让 `IsBlocking` 抢先、不要 `QuickMelee` 特例 | 分流里跳过 Block 分支 |
| 4 | 发出 `successfulDeflect` | `SendNameEventToPSM`（原版在 WasDeflected 后已有） | 强制完美分支后会自带；若自写分支需手动 Queue |
| 5 | **消费** `successfulDeflect` 并进入反击 | 仅 `MeleeDeflect → MeleeDeflectAttack` 边 | **本思路关键**：见 10.3 |
| 6 | 反击资源存在 | `HasAttackRecord`（`MeleeDeflectAttack0` 等） | 武器无该 record 则进不了/打不出反击；需换武器或补 attack |
| 7 | 慢动作 | `MeleeDeflectAttackEvents.OnUpdate` | 进态后原版会做；若旁路进态则需自调 `SetTimeDilation("deflect", ...)` |

### 10.3 节点 5 的三种实现（可行性排序）

PSM 转移边由状态机资源定义；脚本里的 `ToMeleeDeflectAttack` **只在已处于 `MeleeDeflect` 时**被问询。CET 很难“凭空加一条 Idle→DeflectAttack 边”。因此：

**方案 2a — 强制进入 `MeleeDeflect`，再让原版边消费 `successfulDeflect`（推荐优先试）**

1. 命中时（或命中前一帧）放宽并触发进入 `MeleeDeflect`：  
   `Override("MeleeDeflectDecisions", "EnterCondition", ...)` 在自动模式下返回 true；并制造一次等价于 `IsBlockPressed` 的进入机会，或配合其它已存在的入边。
2. `Override` / 改写 `ProcessDefensiveState`：玩家被近战打中时只打 `WasDeflected`（+ `successfulDeflect`）。
3. 若当帧已在 `MeleeDeflect`（或下一次 PSM tick 仍在窗口内），原版 `ToMeleeDeflectAttack` 会接到 `successfulDeflect` → 完整 `MeleeDeflectAttack`（动画 + 慢动作 + 攻击 effect）。

风险：同帧“先入 Deflect 再结算命中”在引擎里不一定成立（与思路一相同的 PSM/伤害时序问题）。若当帧进不去，则 `successfulDeflect` 仍可能被浪费 → 需 2b/2c 兜底。

**方案 2b — Override 转移条件 + 保证当前态可转到 DeflectAttack**

- `Override("MeleeDeflectDecisions", "ToMeleeDeflectAttack", ...)` 在自动防反标记下恒 true。  
- 仍要求**当前就是 `MeleeDeflect`**。可与 2a 组合：自动模式下尽量把玩家锁在/推入 Deflect，再放宽 ToDeflectAttack。

**方案 2c — 旁路 PSM：命中后直接复刻 `MeleeDeflectAttack` 副作用（控制力最强）**

在确认 `WasDeflected`（`ObserveAfter` `ProcessDefensiveState` / `OnHitBlockedOrDeflected` / 自写分流）之后主动：

1. `TimeSystem.SetTimeDilation("deflect", slowMoAmount, slowDuration, ...)`（参数对齐 `MeleeDeflectAttackEvents` 的 static 默认值）。
2. 将 MeleeWeapon 黑板置 `20`（`DeflectAttack`），并 `PushAnimationEvent` / 走武器 `GetAttack("MeleeDeflectAttack" + N)` → `PrepareAttack` / `StartAttack`（对齐 `MeleeAttackGenericEvents` 出招）。
3. 可选：rumble、tutorial fact、语音 `meleeDeflect` 等。

优点：不依赖是否在 `MeleeDeflect`、不依赖状态机边是否存在。  
缺点：等于手写半套攻击态，要自己处理取消、冷却、与其它近战态冲突；和原版 PSM 可能双轨打架，需要互斥（例如短时禁止普通连招态）。

### 10.4 子弹完美弹反在思路二下怎么做

子弹没有 `MeleeDeflectAttack` 反击态；特殊效果在 **`WasBulletParried` → `ProcessBulletDeflect`（`..._ParryDeflect` + 准星吸附）**。

思路二对应动作：

1. Override `ProcessDefensiveState` 子弹分支：在玩家持刀剑被远程命中时，**直接** `WasBulletParried`（跳过 `IsBlocking` 优先、可一并放宽 `CanBlockBullet`/耐力/技能，按产品需求）。
2. 若还要 **Deflect 举刀动画**：仍需进入 `MeleeDeflect` 或自行 `PushAnimationEvent("Deflect")`（命中反馈里子弹走 `MeleeBulletDeflect`，与近战防反不是同一套）。
3. 不要只加 `IsDeflecting` 却仍保留更高 `IsBlocking`——原版会先打成 `WasBulletDeflected`（普通弹反）。

### 10.5 思路二可行性总评

| 维度 | 评估 |
|---|---|
| 相对思路一 | **可行性更高（若接受 Override/旁路）**：不赌 hitscan/PreAttack 提前量；命中帧即可强制 A 段 |
| 相对“只改 IsDeflecting” | **必须多做 B 段**：否则必现“能挡+敌人震慑、无反击动画/无慢动作” |
| 推荐落地顺序 | ① Override 伤害分流只走完美标记 → ② 验证 A 段与实测一致 → ③ 接 B：优先 2a/2b 进 `MeleeDeflectAttack`；不行再用 2c 复刻慢动作+出招 |
| 主要风险 | PSM 同帧进入；武器缺 `MeleeDeflectAttack` record；2c 与原版近战态冲突；放宽朝向/技能后手感过“作弊” |
| 仓库可参考模式 | `Ninja`/`Knife`/`EquipAttackLeap` 的 `Override(...Decisions, "ToMelee...")`；慢动作可参考现有 TimeDilation 工具 |

### 10.6 两思路对照

| | 思路一（§9） | 思路二（§10） |
|---|---|---|
| 策略 | 提前开真窗口，原版链条原样跑 | 改判定 + 打通/复刻 B 段 |
| 依赖提前感知 | 强 | 弱（命中时即可处理 A；B 需进态或旁路） |
| 只改 `IsDeflecting` | 同思路二：不够 | **明确不够** |
| 完整防反动画+慢动作 | 窗口内命中则自动有 | 必须显式保证进入或复刻 `MeleeDeflectAttack` |
| 实现侵入性 | 输入/Observe 为主 | Override 伤害 + PSM/旁路，侵入更大、闭环更稳 |
