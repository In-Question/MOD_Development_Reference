# 下落机制分析

脚本里和下落有关的是三条管线。落地伤害按垂直速度选落地类型，再由落地状态放出攻击记录。狂暴落地和钝器地面猛击共用 `superheroFall` / `superheroLand`。落在 NPC 头顶上走交互层 `AerialTakedown` 和压制状态机，不读落地类型。

掉多少血、会不会死，写在攻击记录或压制效果里，不在这些脚本里。

垂直速度向下为负。比较时用“更小或等于”，所以落得越快，越先命中更严重的那一档。

## 1. 速度和高度怎么换算

`LocomotionTransition.GetFallingSpeedBasedOnHeight`（`locomotionTransitions.swift` 约 214 行）把一段高度换成等效下落速度：

```text
加速度 = abs(upwardsGravity，缺省再退到 defaultGravity，缺省 -16)
速度 = -加速度 * sqrt(2 * 高度 / 加速度)
高度 <= 0 时速度为 0
```

反向换算是 `GetInitialHeightBasedOnFallingSpeed`。重力取状态机静态参数 `upwardsGravity`，缺省 `-16`。脚本里的高度缺省只在参数缺失时使用，真实高度在运动状态机的静态参数里，仓库里没有这组最终数值。

按缺省重力 `-16`，高度 `h` 的等效速度约为 `-sqrt(32 * h)`。这只用于理解公式，不能当成游戏里“摔死要多高”。

## 2. 落地类型

`LandingType`（`Definitions/Game_Definitions/enums/LandingType.lua`）：

| 枚举 | 值 | 含义 |
| --- | --- | --- |
| Off | 0 | 还没落到会播落地的速度 |
| Regular | 1 | 普通落地 |
| Hard | 2 | 较重落地 |
| VeryHard | 3 | 重落地 |
| Superhero | 4 | 狂暴落地 / 地面猛击 |
| Death | 5 | 坠亡 |

空中状态进入时（`LocomotionAirEvents.OnEnter`，约 3630 行）用高度参数算出五档速度阈值，写成永久参数：

| 永久参数 | 高度参数 | 脚本缺省高度 |
| --- | --- | --- |
| RegularLandingFallingSpeed | regularLandingHeight | 0.10 |
| SafeLandingFallingSpeed | safeLandingHeight | 0.10 |
| HardLandingFallingSpeed | hardLandingHeight | 1.00 |
| VeryHardLandingFallingSpeed | veryHardLandingHeight | 1.00 |
| DeathLandingFallingSpeed | deathLanding | 1.00 |

`deathLanding` 这个参数名没有 `Height` 后缀，但传给的是同一个高度换算。

每帧分类在 `LocomotionAirEvents.OnUpdate`（约 3657 行）。人还在空中时读取垂直速度，从严重到轻微依次比较：

1. 速度 `<= DeathLandingFallingSpeed`：`Death`，黑板 `PlayerStateMachine.Fall = 5`（`DeathFall`）
2. 否则 `<= VeryHardLandingFallingSpeed`：`VeryHard`，黑板 `Fall = 4`（`VeryFastFall`）
3. 否则 `<= HardLandingFallingSpeed`：`Hard`，黑板 `Fall = 3`（`FastFall`）
4. 否则 `<= SafeLandingFallingSpeed`：`Regular`，黑板 `Fall = 1`（`RegularFall`）；水平速度再低于 `maxHorizontalSpeedToAerialTakedown`（缺省 0）时黑板改成 `2`（`SafeFall`）
5. 否则 `<= RegularLandingFallingSpeed`：仍是 `Regular`，但不改上面的黑板分支
6. 否则：`Off`

黑板枚举是 `gamePSMFallStates`（`orphans.swift` 约 6930 行）。黑板 `Fall` 和永久参数 `LandingType` 不是同一套数字。重落地的黑板是 `4`，枚举 `VeryHard` 是 `3`。着地过渡读的是永久参数 `LandingType`（`GetLandingType`），不是黑板。改黑板不会改落地类型。

`SafeFall` 只在第 4 档里、水平速度足够低时写下。仓库里没有脚本读取 `Fall == 2`。`FallPSMPrereq` 能监听这块黑板，具体哪条数据前提要求 `SafeFall`，不在脚本里。

## 3. 分类什么时候停、什么时候留下来

人已经着地时，这一帧只把 `m_resetFallingParametersOnExit` 设为真，然后返回，不再改 `LandingType`。离开空中状态时，只有这个标记为真才调用 `ResetFallingParameters`，把 `LandingType`、`ImpactSpeed`、`InAirDuration` 清零。

人还没着地就离开空中状态时，标记为假，`LandingType` 保持离开前的最后一帧。地面状态的 `OnEnter`（约 673 行）会把黑板 `Fall` 写成 `0`，但不会清 `LandingType`。所以从下落进入突进这类地面状态时，坠亡类型可以一直留到下次有空中状态再分类，或者留到真正的落地过渡读它。

近战跳跃或身上有 `PlayerMadDashLocomotionBuffer` 时，`OnUpdate` 在分类前返回，这一帧不改 `LandingType`。已经记成 `Death` 之后再进入这种跳跃，旧类型还在。

`DodgeAirEvents` 继承空中事件，它的 `OnUpdate` 会调用父类，所以短空中闪避仍在分类。买了长突进后，空中那次走的是 `DodgeEvents`，父类是地面事件，待在突进里的期间不会重新分类。

## 4. 着地后进哪个状态

过渡在 `LocomotionAirDecisions`（约 3562 行）。除了特别写出的条件，都要已经着地：

| 过渡 | 条件 |
| --- | --- |
| ToRegularLand | `LandingType <= 1`，且垂直速度 `<= 0` |
| ToHardLand | `LandingType == 2`，且垂直速度 `<= 0` |
| ToVeryHardLand | `LandingType == 3`。不看垂直速度是不是还朝上 |
| ToDeathLand | `LandingType == 5`。同样不看垂直速度方向 |
| ToSuperheroLand | 只要着地。它不读 `LandingType` |

`ToVeryHardLand` 和 `ToDeathLand` 因此会吃掉“人已经着地、但类型还停在重落地或坠亡”的情况，即使这一帧垂直速度已经被清成 0。

重落地、极重落地、坠亡都继承 `FailedLandingAbstractDecisions`。回到站立要状态时间达到 `duration`，缺省 `2.50` 秒。这是倒地时间，不是伤害公式。

着地黑板是另一套枚举 `gamePSMLandingState`：`RegularLand = 1`，`HardLand = 2`，`VeryHardLand = 3`，`DeathLand = 4`，`SuperheroLand = 5`，`SuperheroLandRecovery = 6`。

## 5. 落地伤害

脚本里没有“按速度扣当前生命”的算式。落地状态进入时放出攻击：

| 状态 | 攻击记录 | 入口 |
| --- | --- | --- |
| HardLand | `Attacks.HardLanding` | `PlayHardLandingEffects` |
| VeryHardLand | `Attacks.VeryHardLanding` | `PlayVeryHardLandingEffects` |
| DeathLand | `Attacks.DeathLanding` | `PlayDeathLandingEffects` |
| RegularLand，且冲击速度比 2.50 米的等效速度更负 | `Attacks.PressureWave` | `ShouldTriggerDestruction` |

`PrepareGameEffectAoEAttack`（`defaultTransition.swift` 约 1066 行）用该攻击记录在玩家脚下生成范围攻击，施放者是玩家自己。`SpawnLandingFxGameEffect` 再跑一个名为 `landing` / `fx` 的效果，把同一个 `attackId` 放进去，范围写成 `2`。命中自己还是只命中周围、伤害数值、伤害类型、是否即死，都在这些攻击记录里。仓库里的脚本没有这些记录的伤害字段。

坠亡状态 `DeathLandEvents.OnEnter` 调用 `PlayDeathLandingEffects`，刺激类型却是 `LandingVeryHard`。语音键也是 `veryhardLanding`。致死与否看 `Attacks.DeathLanding`，不看这次刺激广播。

极重落地会把线速度写成 0。坠亡脚本没有这一句。

## 6. 和下落有关的技能与状态

这些条件出现在下落脚本里。能改范围或换落地状态的，和能解锁头顶压制的，不是同一条。

| 脚本里出现的名字 | 脚本实际做的事 |
| --- | --- |
| `BaseStatusEffect.BerserkPlayerBuff` | 空中更新里，垂直速度已经快于 `minFallHeightToEnterSuperheroFall`（缺省高度 0）时，写下 `requestSuperheroLandActivation`。这段不检查技能有没有购买 |
| `Body_Right_Perk_3_1` 等级恰好为 1 | 只在已经进入 `superheroLand` 之后，把猛击范围按 `superheroFallTime / superheroFallTimeToMaxEffect`（缺省 2 秒）放大，上限 1 |
| `CanGroundSlamInAir` / `CanGroundSlamOnGround` | 钝器快攻地面猛击的进入条件。哪个技能或义体把这两个统计标志设上，脚本里没有 |
| `CanLandSilently >= 1` | 落地时不广播落地刺激。攻击照样放出 |
| `FallDamageReduction` | 只出现在属性枚举和属性界面。落地脚本不读它 |
| `CanAerialTakedown` | 只出现在属性枚举。没有任何脚本读取 |
| `CanTakedownSilently` | 头顶压制执行时，没有这个标志就按致死压制的噪音距离广播 |

谁把 `BerserkPlayerBuff` 加上去，不在下落函数里。狂暴落地的脚本门槛是这个状态正在身上，加上落得够快。

### 狂暴下落

请求写下之后，人进入 `superheroFall`。还没到最大高度时，落地类型直接写成 `Superhero`，不再走坠亡比较。离地距离达到 `maxDistToGroundFromSuperheroFall`（缺省 `20`）后，这个保护结束，之后按普通五档分类，仍然可以变成 `Death`。

`SuperheroFallEvents.OnEnter` 推动画事件 `SuperHeroFall`，并按静态参数 `downwardsImpulseStrength`（缺省 0）加一个向下冲量。离开时把本状态时间写成 `SuperheroFallTime`。

着地进 `superheroLand`。`SuperheroLandEvents.OnUpdate` 在延迟之后放出 `Attacks.GroundSlamFar` 和 `Attacks.GroundSlamNear`，不是 `DeathLanding`。空中落下时延迟读 `aerialPressureWaveSpawnDelay`（缺省 `0.30`），并推动画事件 `SuperheroLand`。然后加上 `BaseStatusEffect.GroundSlamCooldown`，广播 `Explosion`。

动画特征 `SuperheroLand` 的 `state`：悬停 `1`，狂暴下落 `2`，着地 `3`，起身 `4`，离开时写回 `0`。

`SuperheroFallDecisions` 自己的着地过渡只覆写了 `ToDeathLand`：已经着地，并且永久参数 `DeathLandingHeight` 的高度高于玩家当前 Z。这个高度没被写过时，一着地就为真。`AirHoverEvents` 里有写这个高度的函数。狂暴下落若没经过那段悬停，这条高度比较用的是之前留下的值。

### 钝器地面猛击

`MeleeGroundSlamAttackDecisions` 是另一条入口，进的是同一组 locomotion 状态。条件是：

- 在地面要有 `CanGroundSlamOnGround`，在空中要有 `CanGroundSlamInAir`
- 这一下是快攻
- 当前武器是钝器
- 身上没有 `BaseStatusEffect.GroundSlamCooldown`
- 当前 locomotion 是站、跑、蹲、瞄准走、各类跳、下落、滑落或突进之一
- 胶囊体能放下，缺省高 `1`、半径 `1`
- 不在移动电梯里

进入后写下临时参数 `groundSlam`。`AirHoverDecisions` 看到它就进入悬停。悬停再进 `superheroFall`：`autoTransitionToSuperheroFall` 缺省为真，且 `maxAirHoverTime` 缺省为 0，所以脚本缺省下会立刻往下掉。若这个自动过渡被状态机关掉，则要再按蹲。

从地面发动时，永久参数 `groundedGroundSlam` 为真。着地动画事件改成 `GroundSlam`，下落时间按 0 计，着地持续时间读 `groundedStateDuration`（缺省 `0.77`）。空中落下读 `aerialStateDuration`，缺省同样 `0.77`。之后进 `superheroLandRecovery`，缺省再等 `0.40` 秒回站立。

`Body_Right_Perk_3_1` 不参与能不能进这套状态。地面发动时下落时间为 0，即使买了这个技能，范围系数也是 0。

## 7. 落在 NPC 头顶

这条叫空中压制。触发点是 NPC 身上的交互层 `AerialTakedown`，不是 `LandingType`，也不是落地攻击。

`ScriptedPuppet.ToggleInteractionLayers` 给普通 NPC 留着这层。下面这些会关掉它：人群、`canGrappleCivilian` 为假时的平民、带 `ImmuneToTakedown` 的首领、大体型、商人。NPC 倒地时关掉，复活时重新打开。`player.grapple.canGrappleCivilian` 的脚本缺省是真。

层激活后，`ScriptedPuppetPS.PushChoicesToInteractionComponent` 看到标签 `AerialTakedown` 就不弹出交互选项，直接调用 `PushAerialTakedownActionEventToPSM`：

- `StartTakedownEvent.actionName = LeapToTarget`
- `slideTime = 0.30`
- `target` 是这个 NPC
- 同时对目标执行记录 `Takedown.AerialTakedown`

玩家状态机 `OnStartTakedownEvent` 加上 `LocomotionTakedown`，并把 `Record1DamageInHistoryEvent` 发给目标。

`TakedownLeapToPreyDecisions` 在动作名是 `LeapToTarget` 时进入。`TakedownLeapToPreyEvents.OnEnter` 停掉名为 `falling` 的特效，播放 `lcm_falling_wind_loop_end`，把黑板 `PlayerStateMachine.Takedown` 写成 `3`。

离开这次跃击有两条脚本条件：

- 状态时间达到 `maxDuration`，缺省 `3` 秒，进结束
- `CollisionBetweenPlayerAndTarget` 为真时也进结束。这个函数名查的是玩家脚下的静态几何：从玩家位置向下，最大距离 `0.50`。查到几何时，进入执行压制的条件返回假

两条过渡在状态机里谁先被检查，脚本没有写。

`TakedownExecuteTakedownEvents.OnEnter` 如果当前动作仍是 `LeapToTarget`，把要执行的名字改成 `AerialTakedown`。然后 `SelectAerialTakedownWorkspot` 拼工作点名字，用效果名 `takedowns`、效果标签等于这个名字跑一次效果。这就是专用动作的入口。

工作点名字从 `AerialTakedown` 开始：

1. 玩家前向和目标前向的夹角绝对值小于 `90`：加上 `_Back`。夹角大于等于 `90` 时保持原名
2. 右手武器类型是 `Cyb_MantisBlades`：再加上 `_MantisBlades`
3. 否则，目标前方 `1` 米没有路，或玩家前方空间不够（宽 `0.35`、高 `0.90`、距离 `minRequiredSpace` 缺省 `0.10`）：再加上 `_Simple`

所以脚本能拼出的名字是 `AerialTakedown`、`AerialTakedown_Back`，以及这两个再接 `_MantisBlades` 或 `_Simple`。左右方向的参数在这次调用里是假，没有左右变体。

随后效果标签换成 `setUnconsciousAerialTakedown`，再跑一次 `takedowns`。这个标签和普通非致死压制、大体型压制一样，给 NPC 发动作信号 `takedown_defeat`。普通致死压制用的是标签 `kill`，并调用 `SetMyKiller`。空中压制不走那一支。

数据统计把 `ETakedownActionType.AerialTakedown` 记入 `gmpl_npc_incapacitated_by_player`，和击杀计数 `gmpl_npc_killed_by_player` 分开。目标最后是倒地还是死亡，还要看 `Takedown.AerialTakedown` 和这个效果在数据里的结算，脚本这段只发出击败信号。

玩家没有 `CanTakedownSilently` 时，`TriggerNoiseStim` 把空中压制和致死压制放在同一档，按 `AIGeneralSettings.takedownNoiseRange`（缺省 `3`）广播 `SoundDistraction`。更短的 `takedownLessNoiseRange` 只给非致死压制和抛尸。

`AnimFeature_AerialTakedown` 只有一个整数 `state`。带 `DisableCameraControl` 的工作点进入时写成 `1`，离开写成 `0`。它关镜头控制，不负责选上面的工作点。

`TakedownLeapToPreyEvents.RequestPositionAdjustmentWithParabolicMotion` 写了按目标位置做位移，仓库里没有调用它的地方。脚本能确定的位移相关数值只有事件上的 `slideTime = 0.30`，以及跃击状态里那几个缺省为 0 的静态参数名：`horizontalDisplacement`、`slideDuration`、`distanceRadius`、`rotationDuration`。

交互层要离头顶多近、要不要先变成 `SafeFall`，都在交互数据里，不在这些函数里。脚本侧和“够不够垂直”有关的唯一写入，是第 2 节那个 `SafeFall`：垂直速度已经落在安全档，并且水平速度不超过 `maxHorizontalSpeedToAerialTakedown`。这个上限的脚本缺省是 `0`。真实数值在状态机静态参数里。

之后若把这具身体捡起来，`PickUpEvents` 看到动作类型仍是 `AerialTakedown` 时，把拾取动画参数写成 `3`。那是搬尸体，不是这次下落本身。

## 8. 下落太快不能进某些状态

`IsCurrentFallSpeedTooFastToEnter` 只在离地时生效：垂直速度 `<= VeryHardLandingFallingSpeed` 就拒绝。这是进入某些动作的门槛，不是伤害结算，也不是头顶压制的条件。阈值和重落地用的是同一个永久参数，所以它要等空中状态至少进入过一次、阈值已经被写上。人在地面时这个函数直接返回假。

## 9. 改这些机制时要注意

- 清掉垂直速度不会自动清掉已经写成 `Death` 或 `VeryHard` 的 `LandingType`。着地过渡读的是这个记录。
- 清黑板 `Fall` 也不等于清 `LandingType`。`SafeFall` 只影响读这块黑板的数据前提，不改变落地伤害分档。
- 人还在空中就离开空中状态时，记录会留下。回到空中状态后，下一帧 `OnUpdate` 会按当时的垂直速度重写，除非该帧因跳跃标记提前返回。
- 落地伤害记录路径是 `Attacks.HardLanding`、`Attacks.VeryHardLanding`、`Attacks.DeathLanding`、`Attacks.PressureWave`。狂暴着地是 `Attacks.GroundSlamFar` 和 `Attacks.GroundSlamNear`。脚本没有它们的伤害数值。
- 高度门槛的脚本缺省都很小，而且硬落地、重落地、坠亡的缺省高度都是 `1`。真实分档以状态机静态参数为准。
- 头顶压制的专用动作是效果 `takedowns` 上的工作点名。改 `LandingType` 或落地攻击不会换这套动作。
- `CanAerialTakedown` 没有被脚本读取。交互层开关在 `ToggleInteractionLayers`。

## 10. 下落击杀模组

`ModExamples/AerialTakedown/init.lua` 只做头顶下落击杀。不改 `LandingType`，也不拦截 `Attacks.PressureWave`。较重落地、重落地、坠亡仍按原版分档结算。摔伤和坠亡由玩家用跳跃自己避开。

人在空中、竖直速度已经小于等于 `SafeLandingFallingSpeed`、且不是 `superheroFall` 时，`GetLookAtObject(player, true, true)` 看到对象就通过注视判定。视线离开后，这个对象再保留 `0.30` 秒，期间也算通过。不再累计注视时长。距离默认不超过 `5` 米，买了 `Reflexes_Central_Perk_2_1` 则乘 `2`。`1` 米只用来插值滑行时间（`0.05` 到 `0.25` 秒），近于 `1` 米也会突进。还要已买 `Reflexes_Central_Milestone_2` 到 `2`，以及空中突进 `Reflexes_Central_Milestone_3` 到 `3`。同一段滞空只跃一次。

规则满足时发一张 `3` 秒的通行票据：直接排队 `StartTakedownEvent`（`LeapToTarget`）并执行 `Takedown.AerialTakedown`。票据有效期内，`TakedownLeapToPreyDecisions` 的进入条件视为通过，脚下 `0.50` 米地面检测不再中止跃击，也不再因此结束该状态。这段时间里原版交互层再激活则不再重复发送。

满足后用 `adjustTransform` 滑到目标脚底正上方 `3.20` 米，并播放突进的 `lcm_dash`、`dash` 特效、`Dodge` 动画事件和 `medium_pulse` 震动。不挂 `PlayerMadDashLocomotionBuffer`，否则空中更新会跳过下落分档。滑行过程中不改速度。滑行结束后把水平速度写成 `0`、竖直速度写成 `SafeLandingFallingSpeed`，保持到这段收尾结束。这只发生在这一次跃击之后，用来从头顶上方再落下来穿过交互层，不是全局的落地保护。踩头仍由原版交互层进入体积后自己触发。跃击状态下玩家脚下 `0.50` 米内已有地面就结束、不播动作，这条原版限制没有改。
